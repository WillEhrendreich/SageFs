🏗️  ARCHITECTURE TIERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Tier 1: ELM PROGRAM (Pure, Testable, Replay-able)
  ├─ Update:  Msg → Model → Model * Effect list
  ├─ Render:  Model → RenderRegion list
  ├─ File:    SageFs.Core/ElmDaemon.fs
  └─ No I/O:  All side effects via Effect dispatch

Tier 2: EFFECT HANDLER (Async)
  ├─ Execute side effects (session ops, worker comm)
  ├─ Dispatch results back to Elm loop
  ├─ File:    SageFs.Core/SageFsEffectHandler.fs
  └─ Pattern: (Msg → unit) → Effect → Async<unit>

Tier 3: WORKER PROCESS (Isolated)
  ├─ One per session (separate OS process)
  ├─ FSI instance + hot reload + file watch
  ├─ Live test execution + coverage tracking
  ├─ File:    SageFs/WorkerMain.fs
  └─ Comm:    Named pipes + HTTP

🚀 DAEMON STARTUP SEQUENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. SageFs/Program.fs:139-378
   ├─ Parse CLI command
   ├─ Route to appropriate handler (daemon/tui/gui/worker/jupyter)
   └─ Default: Daemon mode

2. DaemonMode.run(mcpPort, flags)
   ├─ Create SessionManager (MailboxProcessor actor)
   ├─ Create CQRS snapshot reader
   └─ Pass to ElmDaemon.start

3. ElmDaemon.start(deps, onModelChanged)
   ├─ Create Elm program
   ├─ Wire effect handler
   └─ Return: ElmRuntime<Model, Msg, Region>

4. ElmLoop.start(program, initialModel, cancellationToken)
   ├─ Dedicated drain thread (not thread pool)
   ├─ ConcurrentQueue<Msg> for dispatch
   ├─ ManualResetEventSlim for signaling
   ├─ Phase 1: Drain all queued messages
   ├─ Phase 2: Run Update (pure)
   ├─ Phase 3: Execute Effects (async)
   ├─ Phase 4: Render (once per batch)
   └─ Return: ElmRuntime with Dispatch/GetModel/GetRegions

5. Message Loop (continuous)
   ├─ Listeners dispatch UI actions
   ├─ Effects return results as new messages
   ├─ Worker SSE events broadcast to clients
   └─ File watcher triggers reload/soft-reset

💾 BINARY PERSISTENCE (.sagefs Session Format)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Format: .sagefs v3 (Magic: "SFS3")

Layout:
  ┌─────────────────────────┐
  │ Header (64 bytes)       │ Magic + version + CRC
  ├─────────────────────────┤
  │ Section Directory       │ Tag → Offset/Size map
  ├─────────────────────────┤
  │ Section: META           │ Session metadata strings
  │ Section: INPT           │ Interactions + pools
  │ Section: REFS           │ Assembly references
  │ Section: PROF (opt)     │ Profiling data
  │ Section: BIND (opt)     │ Runtime bindings
  └─────────────────────────┘

String Encoding:
  lp-string:        u32(length) + u8[length]
  lp-string-option: 0xFFFFFFFF (None) | lp-string (Some)

Design Rationale:
  ✓ One format for disk + wire (no transcode overhead)
  ✓ Binary from day one (4-8× faster than JSON)
  ✓ Section-based extensibility (unknown sections skipped)
  ✓ CRC-32 at two levels (header + per-section)
  ✓ Schema compiled into reader (no inline metadata)
  ✓ Validate early, trust late (check CRCs on open)
  ✓ Human-inspectable (xxd shows magic, size, structure)

Performance: 30-100ms to read, 50-200ms to write (depends on interaction count)

🔥 HOT RELOAD (No Restart, No Rebuild)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Timeline:
  1. FileWatcher detects .fs change
     └─ 500ms debounce (configurable)
  
  2. Emit "Compiling..." via SSE
     └─ Browser shows overlay
  
  3. Send #load to FSI
     └─ hotReload=true in Args
  
  4. FSI generates new assembly
     └─ Returns dynamic types
  
  5. Harmony method patching
     └─ Fuzzy-match methods
     └─ Patch method pointers at runtime
     └─ No restart, no restart
  
  6. Broadcast "Reload" via SSE
     └─ Browser green flash + auto-refresh
  
  7. Next HTTP request uses new code
     └─ Instant (no manual F5)

On Error:
  ├─ FSI returns FS#### diagnostics
  ├─ Broadcast "CompilationFailed"
  ├─ Browser shows red error overlay
  └─ Pauses reload (no thrashing)

Safety Features:
  • Infinite-reload guard (sessionStorage counter >3 in 5s → pause)
  • Error overlay (red panel with source context)
  • Idempotent injection (data-sagefs-injected prevents dupes)
  • Kill switch (SAGEFS_DEVRELOAD=0)
  • SSE retry (retry: 1000ms auto-reconnects)

⚡ LIVE TESTING (3-Speed Feedback Pipeline)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Speed 1: ~50ms (Tree-Sitter Detection)
  → Scan .fs file for test attributes
  → Works on broken/incomplete code
  → Emit immediate gutter markers
  → Result: ✓/✗/● markers appear before you save

Speed 2: ~350ms (F# Compiler Service)
  → Type-check file
  → Extract symbol uses (FullName, UseKind)
  → Build dependency graph (symbol → test mapping)
  → Compute affected tests
  → Result: Know which tests matter for this change

Speed 3: ~500ms (Affected-Test Execution)
  → Run only impacted tests (not all)
  → IL-level coverage tracking
  → Failure analysis + causal narration
  → Emit SSE events (test_results_batch, failure_narratives)
  → Result: ✓/✗ + Expected vs Actual + reason for failure

Test Categorization & Run Policies:
  Unit       → OnEveryChange    (run during editing)
  Integration → OnSaveOnly       (run on file save)
  Browser    → OnDemand         (manual trigger)
  Property   → OnEveryChange    (FsCheck fuzzing)
  Benchmark  → OnDemand

📊 FAILURE NARRATIVES (Why Did This Test Break?)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Flakiness Detection:
  → Track last 10 outcomes in circular buffer
  → Count flip events (pass↔fail)
  → Insufficient: <3 samples
  → Stable: ≤2 flips in 10 runs
  → Environmental: ≥2 flips (auto-quarantine)
  → PropertyCounterexample: FsCheck shrunk case

Causal Analysis:
  → Diff symbols between last pass and current failure
  → Map changed symbols to test coverage
  → Generate human-readable narrative

Data Structure:
  type FailureNarrative = {
    LastPassedAt: DateTimeOffset         // When it last passed
    TimeSinceLastPass: TimeSpan           // How long broken
    CausalChanges: CausalChange list      // What probably caused it
    PropertyViolation: string option      // FsCheck counterexample
    Summary: string                       // Human summary
  }

  type CausalChange =
    | SymbolChanged of string     // Function/type changed
    | FileChanged of string       // File changed
    | Unknown                     // Can't determine

Example:
  Test: should_add_two_numbers (FAILED)
  LastPassedAt: 2026-03-02T14:30:00Z
  TimeSinceLastPass: 2h 15m
  CausalChanges: [SymbolChanged "mathLib", FileChanged "math.fs"]
  Summary: "Test started failing after mathLib was refactored. 
            Check the recent changes in math.fs"

🛡️ ERROR HANDLING (39 Unified Error Cases)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Unified Type: type SageFsError = 

Session Errors:
  | SessionNotFound of sessionId
  | NoActiveSessions
  | SessionCreationFailed of reason
  
Worker Errors:
  | WorkerCommunicationFailed of sessionId * reason
  | WorkerSpawnFailed of reason
  | WorkerTimeout of sessionId * operation * timeoutSec
  
Eval Errors:
  | EvalFailed of reason
  | ResetFailed of reason
  | HotReloadFailed of path * reason
  
Infrastructure:
  | DaemonStartFailed of reason
  | PortInUse of port
  | SseConnectionError of reason
  | Unexpected of exn

Pattern: Result<'T, SageFsError> everywhere
  → Compiler enforces exhaustive matching
  → No bare catches
  → User-facing message via SageFsError.describe()

Auto-Recovery:
  → Standby pool swaps for instant recovery
  → Watchdog auto-restart with exponential backoff
  → Partial feature availability on errors
