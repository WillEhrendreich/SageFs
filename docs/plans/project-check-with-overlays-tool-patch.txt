## 1. The tool (`SageFs/McpTools.fs`)

After `list_references`. The whole body is `CheckProject.answer`, so nothing longer than a few lines goes in this file.
`CancellationToken` is bound by the MCP SDK to the request, so a `notifications/cancelled` for the call cancels it, which stops
the MSBuild process tree or the compiler check. No existing tool takes one, so confirm the SDK version binds it before relying
on it: call the tool, cancel it from the client, and watch the `dotnet msbuild` child exit.

```fsharp
    [<McpServerTool>]
    [<Description("""Type-check a whole F# project, with some files replaced by text you send, without building and without touching any session. Answers "does the project still compile with this change". `overlays` is a JSON array of {"path": ..., "text": ...}, one for each project file you replaced; a path that is not a source file of the project is refused with the project's files. The reply is Clean, or each diagnostic as `path(line,col): severity code: message`, errors first. A referenced project that is behind its sources is built once first and the reply says so. Compiler arguments are kept until the project file, Directory.Build.props, Directory.Build.targets or Directory.Packages.props changes. `__SOURCE_DIRECTORY__` inside an overlaid file names a temporary directory.""")>]
    member _.check_project(
        [<Description("Path to the .fsproj, absolute or relative to working_directory.")>]
        project: string,
        [<Description(WorkingDirectoryParam)>]
        [<Optional; DefaultParameterValue("")>]
        working_directory: string,
        [<Description("JSON array of {\"path\": \"...\", \"text\": \"...\"}. Empty checks the project as it is on disk.")>]
        [<Optional; DefaultParameterValue("")>]
        overlays: string,
        [<Description("Build configuration the project is checked in. Empty means Debug.")>]
        [<Optional; DefaultParameterValue("")>]
        configuration: string,
        cancel: System.Threading.CancellationToken
    ) : Task<string> =
        let resolved = match System.String.IsNullOrWhiteSpace working_directory with | true -> project | false -> System.IO.Path.GetFullPath(project, working_directory)
        logger.LogDebug("MCP-TOOL: check_project called, project={Project}", resolved)
        SageFs.Features.CheckProject.answer resolved configuration overlays cancel |> withEcho ctx "check_project"
```

The description is about 770 characters. If the tool-list budget is lower, drop the last two sentences first.

## 6. The docs

A row in the table of `docs/mcp-tools.md`, next to `check_fsharp_code`:

> | `check_project` | Type-check a whole project with some files replaced by overlays, without building and without a session. Arguments `project`, `working_directory`, `overlays` (JSON array of `{path, text}`), `configuration`. Reply is `Clean`, or one line for each diagnostic, `path(line,col): severity code: message`, errors first, at most 50 then a count of the rest; a refusal (an overlay for a file the project does not compile, an argument list with no FSharp.Core) says what it was; a cancelled or timed out check says which stage stopped. Compiler arguments come from a design-time MSBuild run and are kept until the project file, `Directory.Build.props`, `Directory.Build.targets`, `Directory.Packages.props`, `global.json` or the restore's assets change, and the reply's first line says whether they were kept or read and why. A referenced project whose output is missing or older than its inputs is built once, deepest first, and named. Overlays are written to `<temp>/sagefs-project-check/` and the compiler is pointed at them, so `__SOURCE_DIRECTORY__` in an overlaid file names that directory. |
